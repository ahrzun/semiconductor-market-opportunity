# Dashboard build guide

> Illustrative dataset constructed to be directionally consistent with publicly reported
> industry estimates. Figures are for methodology demonstration and are not market research.

This guide assumes you have Power BI Desktop open, have never seen this dataset, and want the
three-page report built without asking anyone a question. Follow it top to bottom. It takes
about 45 minutes.

A `.pbix` is a binary file that cannot be generated by the Python pipeline, so it is not
committed. This guide is the deliverable that replaces it.

Before you start, run `make all` in the repository root. Everything below reads from
`data/processed/`, which that command regenerates.

---

## Part 1 - Load the data

### 1.1 Import the four CSVs

**Home > Get data > Text/CSV.** Import these one at a time from `data/processed/`:

| File | Name the query |
|---|---|
| `dim_segment.csv` | `dim_segment` |
| `fact_segment_year.csv` | `fact_segment_year` |
| `fact_opportunity_score.csv` | `fact_opportunity_score` |
| `fact_sensitivity.csv` | `fact_sensitivity` |

For each one, click **Transform Data** rather than Load, and check in Power Query that:

- the first row is promoted to headers;
- `year` is **Whole Number**;
- every `*_usd_bn`, `*_pct`, `norm_*`, `contrib_*` and `opportunity_score` column is
  **Decimal Number**;
- `rank_in_year`, `base_rank`, `rank_shift` and `is_base_profile` are **Whole Number**;
- `segment_id`, `profile` and every name or label column is **Text**.

Power Query's type detection gets `year` wrong often enough to matter - if it lands as Text the
`dim_year` relationship will not form.

### 1.2 Build the contribution bridge

Still in Power Query:

1. Right-click `fact_opportunity_score` in the Queries pane > **Duplicate**.
2. Rename the duplicate `bridge_factor_contribution`.
3. Select the seven `norm_*` columns > right-click > **Remove Columns**.
4. Also remove `opportunity_score` and `rank_in_year`.
5. Select `segment_id` and `year` (Ctrl-click) > **Transform > Unpivot Other Columns**.
6. Rename the resulting `Attribute` column to `factor` and `Value` to `contribution`.
7. **Transform > Replace Values** on `factor`: replace `contrib_` with nothing.
8. Add a readable label. **Add Column > Conditional Column**, name it `factor_label`:

   | If `factor` equals | Then |
   |---|---|
   | `serviceable_market_size` | `Serviceable market size` |
   | `cagr` | `CAGR` |
   | `design_services_addressability` | `Design-services addressability` |
   | `strategic_fit` | `Strategic fit` |
   | `customer_demand` | `Customer demand` |
   | `competitive_intensity` | `Low crowding` |
   | `entry_feasibility` | `Entry feasibility` |

   `competitive_intensity` is labelled **Low crowding** on purpose. The stored contribution is
   already inverted, so a tall bar means an uncrowded segment. Labelling that bar "competitive
   intensity" reads backwards to every viewer.

9. **Home > Close & Apply.** You should have 560 rows in `bridge_factor_contribution`.

### 1.3 Add the two calculated tables

**Modeling > New table**, once for each:

```
dim_year =
SELECTCOLUMNS ( GENERATESERIES ( 2021, 2030, 1 ), "year", [Value] )
```

```
dim_profile =
SUMMARIZE (
    fact_sensitivity,
    fact_sensitivity[profile],
    fact_sensitivity[profile_label],
    fact_sensitivity[is_base_profile]
)
```

### 1.4 Build the relationships

Follow the table in `model_relationships.md`. **Decline Power BI's autodetect prompt** - it
links the two 80-row facts directly to each other and creates an ambiguous filter path.

Then apply the hidden-fields and sort-order steps at the end of that file. Setting
`dim_segment[segment_name]` to sort by `forward_mean_score` descending is what makes every
categorical axis in the report come out best-to-worst without per-visual sorting.

### 1.5 Add the measures

Open `measures.dax`. Each block separated by a blank line is one measure. For each:
**Modeling > New measure**, paste, press Enter. Keep the names exactly as written - the field
placements below refer to them verbatim.

Set formatting as you go:

| Measure | Format |
|---|---|
| `Total TAM (USD bn)`, `Total Serviceable Market (USD bn)`, `Unreachable Market (USD bn)` | Decimal, 1 place |
| `Addressable Share %`, `Weighted Avg CAGR %`, `Serviceable Market YoY %`, `TAM YoY %`, `Factor Contribution Share %` | Percentage, 1 place |
| `Opportunity Score`, `Weighted Opportunity Score`, `Score Delta vs Prior Year`, `Factor Contribution` | Decimal, 1 place |
| `Rank by Opportunity`, `Rank Under Selected Profile`, `House View Rank`, `Max Rank Swing vs House View` | Whole number |

## Part 2 - Report-wide setup

Do this once; it applies to all three pages.

**Theme.** View > Themes > Customize current theme. Set the first four theme colours to
`#1B6B45` (prioritize green), `#B07A12` (selective amber), `#9C3A3A` (deprioritize red),
`#1F3864` (neutral navy). Every colour reference below is one of these four.

**Page size.** Format page > Canvas settings > 16:9, 1280 x 720.

**The disclosure footnote is mandatory on every page.** On each of the three pages, drop a
**Card (new)** visual across the bottom of the canvas at X 0, Y 690, width 1280, height 30.
Field: `Data Disclosure`. Turn the category label off, set the value font to 9pt italic grey
`#595959`, background off. This is a modelling obligation, not decoration - do not skip it on
any page, and do not replace it with a text box that can be deleted from one page and not
another.

**Dynamic title.** On each page, a **Card (new)** at X 20, Y 15, width 900, height 40, field
`Dashboard Title`, category label off, 16pt semibold `#1F3864`. It restates the current segment
and year filters, so a screenshot of the page carries its own filter context.

**Shared slicers.** On each page place:

- a **Slicer** on `dim_year[year]`, style **Between**, at X 960, Y 15, width 300, height 55;
- a **Slicer** on `dim_segment[recommendation]`, style **Tile**, at X 960, Y 75, width 300,
  height 45.

Then **View > Sync slicers**: sync both across all three pages, visible on all three.

## Part 3 - Page 1: Executive Overview

Rename the page tab `Executive Overview`.

### KPI cards

Four **Card (new)** visuals in a row at Y 75, height 95, width 290, at X 20, 330, 640, 950.

| Card | Field | Label to type over the default |
|---|---|---|
| 1 | `Total Serviceable Market (USD bn)` | Serviceable market, USD bn |
| 2 | `Weighted Avg CAGR %` | Weighted average CAGR |
| 3 | `Highest-Scoring Segment` | Highest-scoring segment |
| 4 | `Largest Score Mover` | Largest score mover vs prior year |

Cards 3 and 4 return text, so leave their display units at None. Card 4 is blank when the year
slicer is on 2021, because there is no prior year - that is correct behaviour, not a bug.

Set card 1's callout value colour to `#1F3864`. Give all four a 1px `#D9D9D9` border and 8px
rounded corners.

### TAM versus serviceable market

**Clustered bar chart**, X 20, Y 185, width 610, height 250. Title:
*Between 75% and 96% of every segment's TAM is out of reach*.

- Y axis: `dim_segment[segment_name]`
- X axis: `Total Serviceable Market (USD bn)`, then `Unreachable Market (USD bn)`
- Colour the serviceable series `#1B6B45` and the unreachable series `#D9D9D9`
- Legend: bottom
- Data labels: on, for the serviceable series only

The grey portion is the part of each market a design-services firm cannot sell into. Memory is
the point of the visual: it has the second-largest bar and almost none of it is green.

### CAGR by segment

**Clustered column chart**, X 650, Y 185, width 610, height 250. Title: *Growth and
addressability point at different segments*.

- X axis: `dim_segment[segment_name]`
- Y axis: `Weighted Avg CAGR %`
- Colour by field value: Format > Columns > Colour > fx > **Field value** > `Recommendation Colour`
- Sort by `Weighted Avg CAGR %` descending
- Turn the X axis title off; the segment names are self-explanatory

### 2021-2030 growth lines

**Line chart**, X 20, Y 450, width 780, height 230. Title: *Every segment grows; that is why
size alone cannot rank them*.

- X axis: `dim_year[year]`, type **Categorical** (it is an integer, not a date)
- Y axis: `Total Serviceable Market (USD bn)`
- Legend: `dim_segment[segment_name]`, position right
- Turn markers on; leave smoothing off - the dip in 2023 is a real feature of the data and
  smoothing it away misrepresents the cycle

### Segment share

**Donut chart**, X 820, Y 450, width 440, height 230. Title: *Three segments hold nearly three-quarters of
the serviceable pool*.

- Legend: `dim_segment[segment_name]`
- Values: `Total Serviceable Market (USD bn)`
- Detail labels: category and percent of total, outside
- Inner radius 55%

## Part 4 - Page 2: Opportunity Analysis

Rename the page tab `Opportunity Analysis`.

### The core scatter

This is the centrepiece of the report. **Scatter chart**, X 20, Y 130, width 760, height 400.
Title: *Size, growth, score and crowding, one segment per bubble*.

| Well | Field |
|---|---|
| Values (bubble identity) | `dim_segment[segment_name]` |
| X axis | `Total Serviceable Market (USD bn)` |
| Y axis | `Weighted Avg CAGR %` |
| Size | `Weighted Opportunity Score` |
| Play axis | `dim_year[year]` |

Colour by competitive intensity: Format > Markers > Colour > fx > **Gradient**, based on
`Competitive Intensity`, minimum `#1B6B45` at 37, centre `#B07A12` at 65, maximum `#9C3A3A` at 94.
Those are the actual bounds of the column, so the full colour range gets used.

Then:

- turn category labels on so bubbles are readable without hovering;
- set the X axis to **Logarithmic**. Serviceable market runs from under 1 to 59 USD bn across
  the panel, and a linear axis pushes six of the eight segments into the left margin;
- add a **legend note** as a text box under the chart, 9pt grey: *Bubble size is the
  serviceable-market-weighted opportunity score. Red is a crowded segment, not a bad one.*
  Colour encoding that is not explained will be read backwards.

Press play and watch power electronics: the bubble travels right (market growing) while turning
red and shrinking (crowding, score falling). That single motion is the anomaly, and it is the
most persuasive twelve seconds in the whole report.

### Factor decomposition

**Stacked bar chart**, X 800, Y 130, width 460, height 400. Title: *What is actually driving the
selected segment's score*.

- Y axis: `bridge_factor_contribution[factor_label]`
- X axis: `Factor Contribution`
- Sort by `Factor Contribution` descending
- Data labels on, 1 decimal place
- Colour: single colour `#1F3864`

Set this visual to respond to selection on the scatter: **Format > Edit interactions**, and with
the scatter selected, set this visual to **Filter**. Selecting a bubble decomposes that segment's
score into the seven weighted contributions, which sum to the score shown in the bubble.

Add a **Card (new)** directly above it at X 800, Y 95, height 35, field `Opportunity Score`,
so the reader can confirm the bars sum to the score.

### Sensitivity rank shift

**Matrix**, X 20, Y 545, width 1240, height 130. Title: *Which parts of the ranking are a
property of the data rather than of our weights*.

| Well | Field |
|---|---|
| Rows | `dim_segment[segment_name]` |
| Columns | `dim_profile[profile_label]` |
| Values | `Rank Under Selected Profile`, then `Rank Stability` |

Conditional formatting on `Rank Under Selected Profile`: Format > Cell elements > Background
colour > **Rules**, on `Max Rank Swing vs House View`:

| Rule | Colour |
|---|---|
| is 0 | `#DDEDE4` (green tint - rank holds under every profile) |
| is 1 | `#FBF0D8` (amber tint - moves one place) |
| is greater than or equal to 2 | `#F5DEDE` (red tint - the weights are deciding this one) |

Read it across a row, not down a column. A row of identical numbers is a ranking you can defend
in a leadership review. A row that swings from 1 to 5 - which is what HPC does - is a ranking you
have to argue for on its merits, because the weights, not the data, put it where it is.

## Part 5 - Page 3: Recommendation

Rename the page tab `Recommendation`. This page is read, not explored. Keep the year slicer on
the full range.

### The framework table

**Table** visual, X 20, Y 130, width 760, height 300. Title: *Three segments to prioritize, two
to enter selectively, three to deprioritize*.

| Column | Field |
|---|---|
| Segment | `dim_segment[segment_name]` |
| Recommendation | `dim_segment[recommendation]` |
| Forward mean score | `dim_segment[forward_mean_score]` |
| Serviceable market, USD bn | `Total Serviceable Market (USD bn)` |
| CAGR | `Weighted Avg CAGR %` |
| Rank stability | `Rank Stability` |
| Note | `dim_segment[analyst_note]` |

Sort by `forward_mean_score` descending. Then:

- **Conditional formatting on the Recommendation column**: Format > Cell elements >
  Font colour > fx > **Field value** > `Recommendation Colour`. Set the same measure as the
  background colour with 15% transparency.
- **Data bars on `Forward mean score`**: Format > Cell elements > Data bars, minimum 0,
  maximum 100, positive bar `#1F3864`.
- Word-wrap on for the Note column; set its width to roughly 280px.

### Written rationale

**Text box**, X 800, Y 130, width 460, height 300. Title it *Rationale*. Type:

> **Prioritize - automotive & ADAS, analog & mixed-signal, HPC / AI accelerator ASICs.**
> These three hold the largest serviceable pools and the top three forward scores. Automotive and
> analog also carry the strongest fit with existing ASIC, embedded and VLSI capability, which is
> what turns a market into billable work. HPC is the largest and fastest pool in the set, but it
> is the least stable position in the ranking and should be entered against named accounts
> rather than as a general capability build.
>
> **Selective - silicon photonics, power electronics.** Photonics compounds faster than anything
> else in the set on the smallest base, and the binding constraint is talent, not demand: enter
> through partnership or acquisition rather than by hiring. Power electronics is a hold, not a
> build - see the anomaly below.
>
> **Deprioritize - MEMS & sensors, RF & 5G front-end, memory.** MEMS is easy to enter and easy to
> leave; short design cycles make the revenue hard to staff against. RF is mature and
> concentrated. Memory has the second-largest TAM in the set and almost none of it is reachable:
> under 5% is addressable by an outsourced design house, because the design work stays captive
> inside a handful of integrated device manufacturers. Memory is the reason this analysis scores
> serviceable market rather than TAM.

Format the three lead-ins in the matching colours: green `#1B6B45`, amber `#B07A12`, red
`#9C3A3A`. This is the one colour-coded legend the report uses.

### The anomaly callout

**Text box** with a 2px `#B07A12` left border, X 20, Y 445, width 760, height 130. Title:
*Power electronics: the market grows and the opportunity shrinks*.

> Power electronics TAM rises 56% between 2027 and 2030, and its opportunity score falls 16
> points over the same stretch as competitive intensity climbs 39 points. Announced SiC capacity
> converts to supply, the segment crowds, and the margin pool is competed away while the TAM
> chart is still pointing up. Any framework that ranked on market size alone would have us
> committing capacity into this segment in exactly the years the returns disappear. Hold the
> current position; do not build against it.

To let the reader verify this rather than take it on faith, add a small **Line and clustered
column chart** at X 800, Y 445, width 460, height 130, filtered to power electronics via the
visual's Filters pane:

- X axis: `dim_year[year]` (categorical)
- Column: `Total TAM (USD bn)`, coloured `#D9D9D9`
- Line: `Opportunity Score`, coloured `#9C3A3A`, 3px, markers on

The crossing lines are the entire argument.

### Risks

**Text box**, X 20, Y 590, width 1240, height 95. Title: *What would change this answer*.

> The qualitative 0-100 scores carry 45% of the weight and are analyst judgment, not measured
> data. Competitive intensity is modelled as a smooth path; a single large entrant or exit would
> move a segment faster than this model shows. Nothing here uses customer-level pipeline, win
> rates, or pricing, so the recommendation is about where to look, not about what a specific
> engagement is worth. The three deprioritize calls are the robust ones; the ordering inside the
> prioritize group is weight-sensitive and should be revisited if the weighting is contested.

## Part 6 - Check before you present

Work down this list. Each item catches a specific mistake that is easy to make and embarrassing
to discover live.

1. **Every page carries the disclosure card.** Click through all three.
2. **The year slicer moves all three pages.** Set it to 2027 on page 1 and check pages 2 and 3
   followed. If they did not, sync slicers is not on.
3. **The scatter's play axis runs.** Press play on page 2 and confirm bubbles move and recolour.
4. **The decomposition bars sum to the score.** Select automotive on the scatter; the seven bars
   should total the number on the `Opportunity Score` card above them.
5. **Rank stability reads across.** Memory and RF & 5G should show a stability of "Holds under
   every profile"; HPC should not.
6. **Score cards are blank in 2021.** `Largest Score Mover` and `Score Delta vs Prior Year` have
   no prior year to compare against. Blank is correct.
7. **The scatter's colour legend note is present.** Without it, a viewer reads red as "bad"
   rather than "crowded".
8. **Nothing anywhere is ranked on `Total TAM (USD bn)`.** TAM appears in exactly two places in
   this report: the TAM-versus-serviceable bar on page 1 and the anomaly chart on page 3, and in
   both it is there to make the point that TAM is the wrong ranking variable.

## Refreshing after a model change

If you change a weight in `config/weights.yaml` and re-run `make all`, the processed CSVs change
underneath the report. In Power BI Desktop, **Home > Refresh** picks the new files up; no visual
or measure needs editing, because every measure reads scores from the fact tables rather than
recomputing them. The recommendation bands on page 3 come from `dim_segment[recommendation]` and
will move on their own.
